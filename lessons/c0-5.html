Debugging a broken environment

C0 Computing Environment

Locked. Because C0.4 Git I is not mastered yet. You may read so the catalog is a real map. Do not start the exercises or the assigned reading until this lesson is current. Ratings do not move from a URL.

Objectives

  • Treat a broken environment as a diagnosis, not as a reason to reinstall the universe.
  • Form a hypothesis about PATH, permissions, working directory, or “wrong program with the same name.”
  • Use which/type, echo $PATH, ls -l, and the exact error text as evidence.
  • Fix one failure without AI and without a GUI installer.
  • Write down what you tried so the next failure is faster.

Teaching

Most “my computer is broken” reports in the first month are not broken computers. They are a program that is not on the PATH, a file that is not executable, a command run from the wrong directory, a leftover install from a tutorial, or two versions of a tool and the wrong one answering. Reinstalling Python, deleting .zshrc, or following a new blog post is how a messy machine becomes a haunted one.

Debugging an environment is the same loop we will use on code in C4, only the patient is your shell. You read the error as if it were true. “Command not found” means the shell looked at a list of directories and did not find that name. It does not mean the program does not exist on the disk. “Permission denied” we already covered. “No such file or directory” is often a path or a missing interpreter line at the top of a script. The words are specific. Read them before you change anything.

PATH is a list of directories the shell searches, in order, for a name you typed that is not a built-in. The first match wins. That is why two Pythons can exist and the one you installed is not the one that runs. type and which ask “which program will this name start?” echo $PATH asks “where are we even looking?” If you cannot answer those two, you are guessing.

I will give you broken setups on purpose: a script that is not executable, a PATH that misses a directory, a working directory that is not the project, a file that needs a shebang, a permission that blocks a folder. Your job is a short written diagnosis — what I think is wrong, what I ran to check, what I will change, how I will verify — and then the change. Lucky fixes that you cannot explain do not count.

AI is off for this lesson. A model will happily tell you to curl a script from the internet or to sudo something that did not need sudo. Privilege is not a debugging step. We will talk about when sudo is honest later. Today, if you need it to list your own files, your hypothesis is probably wrong.

Write a lab note. Date, error text verbatim, commands, result, conclusion. This is not bureaucracy. This is how you stop repeating the same thirty minutes next month. I will ask for the note, not for a vibe.

The C0 exam, when we reach it, is this skill on a clean machine description: set up a project, commit, and debug a PATH or permission failure without a GUI and without AI. Everything in C0.1–C0.4 was load-bearing for that hour.

Work

Exercises are listed so you can see the shape of the work. They are not assigned. Do not start them. No solutions on this site.

  1. Closed-resource. I will send a broken script or a broken PATH description in chat. Before you change anything, write: the exact error, your hypothesis, the next command that would falsify it.
  2. On your machine, deliberately break something disposable (remove execute permission from a script you wrote, or run it from the wrong directory). Diagnose it as if you did not do it on purpose. Fix it. Restore.
  3. Find two different binaries that share a common name (python/python3, git, etc. — whatever exists). Record type/which and versions. Say which one your shell will run and why.
  4. Do not reinstall your OS. Do not paste the error into a model. Do not sudo unless I say the problem is actually ownership.

Mastery

Given a PATH or permission failure, you write a hypothesis, run a check that could prove you wrong, and fix the actual cause. No GUI, no AI. This is the C0 exam’s core. The page does not grade you.
