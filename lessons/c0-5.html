Definitions

PATH
The list of folders the shell searches for a program name.
command not found
The shell searched PATH and did not find that name.
permission denied
The file exists, and the rule forbids this action.
no such file
The path you named is not here, or a script names an interpreter that is not here.
which
A program that prints which file a name will start.
hypothesis
A guess you can test with the next command.
shebang
The first line of a script that names the interpreter to run.

command not found

command not found is a search miss. It is not proof the file is absent from the disk.

Most broken computers are not broken

Most my-computer-is-broken reports in the first month are not broken computers. They are a program that is not on PATH, a file that is not executable, a command run from the wrong folder, or two versions of a tool and the wrong one answering.

Reinstalling Python, deleting .zshrc, or following a new blog post is how a messy machine becomes a haunted one. We are not doing that.

Do this now

type date
which date
echo $PATH

type tells you how the shell will resolve the name. which prints a path if it is a file. PATH is the search list.

Read the error as if it were true

Debugging an environment is the same loop we will use on code in C4. The patient is your shell. You read the error as if it were true.

command not found means the shell looked at a list of folders and did not find that name. It does not mean the program does not exist on the disk. permission denied we already covered. no such file or directory is often a path or a missing interpreter line at the top of a script.

Do this now

not-a-real-command
ls /tmp/this-folder-is-not-here

Read both errors. One is a search miss. One is a missing path. Do not change PATH. Do not reinstall anything.

A script that will not run

A file you wrote is not a program until two things are true. The kernel must be allowed to execute it. The first line should name the interpreter, starting with #!

chmod +x file marks execute. If you run ./file and the shell says permission denied, check ls -l. If it says no such file and the file is right there, check the shebang path.

Do this now

cd /tmp
printf '%s\n' '#!/bin/echo' 'hello from a script' > c0-5-script
ls -l c0-5-script
./c0-5-script
chmod +x c0-5-script
./c0-5-script

The first ./ should fail with permission denied. After chmod +x it should run. Write both errors and the fix.

Wrong working directory, wrong binary

A lot of no such file is a relative path run from the wrong folder. pwd first. Then ls. Then the command.

PATH is ordered. The first match wins. That is why two Pythons can exist and the one you installed is not the one that runs. type and which ask which program this name will start. If you cannot answer those two, you are guessing.

Do this now

type python3 || true
which python3 || true
python3 --version || true

Write which binary your shell will run, or write that python3 is missing. Either is a fact.

Write the lab note

Date, error text verbatim, commands, result, conclusion. This is not bureaucracy. This is how you stop repeating the same thirty minutes next month.

If the note says I tried some things and then it worked, we redo the hour. Lucky fixes you cannot explain do not count. I will revert them and wait.

Implement

Closed-resource terminal drills. No Bandit walkthrough. No solutions on this site.

  1. Closed-resource. Before you change anything on a failure I send, write the exact error, your hypothesis, and the next command that would falsify it.
  2. On your machine, deliberately break something disposable. Remove execute permission from a script you wrote, or run it from the wrong folder. Diagnose it as if you did not do it on purpose. Fix it. Restore.
  3. Find two different binaries that share a common name, python3 and python, or git, whatever exists. Record type or which and the versions. Say which one your shell will run and why.
  4. Write a lab note for one of the failures above. Date, error verbatim, commands, result, conclusion.
  5. Do not reinstall your OS. Do not paste the error into a model. Do not sudo unless I say the problem is actually ownership.
