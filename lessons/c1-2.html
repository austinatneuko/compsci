Control flow

C1 Programming Fundamentals in Python

Locked. Because C0 module 3, editor and terminal workflow, is not mastered yet. C1 can start in parallel only after that. You may read so the catalog is a real map. Do not start the exercises or the assigned reading until this lesson is current. Ratings do not move from a URL.

Objectives

  • Write if / elif / else as a choice among paths, not as decoration.
  • Trace a while and a for on paper, including the loop variable.
  • Know that for x in s walks items, not indexes, unless you asked for indexes.
  • Stop a loop on purpose with break, and skip an iteration with continue, only when you can say why.
  • Avoid the infinite loop you did not mean, and kill the one you did.

Teaching

A program that only runs top to bottom is a grocery list. Real programs choose and repeat. Control flow is the name for those two ideas. Nothing fancy. At each if, the machine evaluates a boolean and takes one path. At each loop, it comes back until a condition fails or the collection is exhausted.

Booleans are values, not decorations. == asks whether two things are equal. = binds a name. Mixing them is the first classic bug. and, or, and not have precedence. When you are unsure, parenthesize. Compare with the types you meant. "0" is not 0, and "" is not None. Python has truthiness. Empty containers and zero are false in a boolean context. I want you to know that exists so it does not surprise you. I also want you to write explicit comparisons when the explicitness is the point of the code.

if / elif / else is one chain. The first true condition wins. An if stacked under another if is a nest, not a chain, and it means something else. I will make you draw the paths. If you cannot draw them, you cannot test them.

while is as long as this is true, do this body. You are responsible for the thing that becomes false. If the condition never changes, you have an infinite loop. In a terminal, Ctrl-C is your friend. Force-killing the window is a habit we will break. for is for each item in this iterable, bind the loop variable and run the body. The loop variable is a real name. After the loop it still refers to the last item, if there was one. People who reuse it casually write bugs that only show up on the last element. Those bugs are embarrassing in a review. Learn the name's lifetime now.

You do not need range to walk a list of items. You need range when you need numbers, or indexes. for i in range(len(xs)) is a smell when for x in xs was the job. We will use indexes when the algorithm needs a neighbor, xs[i-1], or a swap. Using them by default is how people import C into Python and then complain that Python is hard.

break leaves the loop. continue skips the rest of this iteration. Both are legal. Both are easy to hide a second algorithm inside. If I cannot see the exit condition at the top of the loop, I will ask you to rewrite.

Trace on paper. I am serious. Take a ten-line fragment, make a table of names, update the table each line. This is the skill the C1 exam uses when I hand you someone else's 50-line function. If you only ever run code and stare at prints, you cannot debug a line that did not print.

Closed-resource drills this week. The midterm will not let you ask a model whether the loop runs four times or five.

Work

Exercises are listed so you can see the shape of the work. They are not assigned. Do not start them. No solutions on this site.

  1. On paper, trace n = 5 / while n > 0: / n = n - 2 / print n. How many prints? What is n after? Then run it.
  2. Write a program that reads a small list of numbers you typed into the file and prints how many are positive, negative, and zero. Use a for-loop over items, not indexes.
  3. Write the same count with a while-loop and an index. Say in a comment which version you would keep and why.
  4. Produce an infinite loop on purpose in a disposable file. Stop it from the terminal. Write the kill key in chat so I know you have it.
  5. Closed-resource. No AI. Quiz at the end of the module.
