Recursion I

C1 Programming Fundamentals in Python

Locked. Because C0 module 3, editor and terminal workflow, is not mastered yet. C1 can start in parallel only after that. You may read so the catalog is a real map. Do not start the exercises or the assigned reading until this lesson is current. Ratings do not move from a URL.

Objectives

  • Explain recursion as a function calling itself on a smaller instance of the same job.
  • Write a base case that does not call, and a recursive case that moves toward it.
  • Trace a small recursion on paper, factorial, a list sum, a simple tree walk preview.
  • Recognize an infinite recursion as a missing or unreachable base case.
  • Know when a loop is the function you actually want.

Teaching

Recursion is not a personality. It is a way to define a function by referring to a smaller version of the same problem. The two pieces you must always be able to point at. A base case that returns without calling itself, and a recursive case that calls on something closer to the base. If either is missing, you get RecursionError or a wrong answer.

The classic examples are small on purpose. Factorial. The sum of a list as first plus sum of rest. A countdown. I do not care if you would have written a loop. I care that you can draw the stack. Each call has its own n, its own place to return to. That stack picture is the same picture C9 will use for C frames. You are paying for that later course now, cheaply.

Trust the recursive call. Beginners reimplement the whole problem inside the recursive case, or they adjust the answer after the call in a way that shows they did not believe it. If sum_rest is correct by induction, C3 will name that, you add xs[0] and you stop fussing. If you cannot yet feel that, trace two or three frames until you do.

Recursion that walks a nested structure, a list of lists, a directory tree, a JSON value, is where the idea earns its keep. A loop wants a flat sequence. A recursive function wants a shape that contains shapes like itself. We will do one nested-list walk. We will not do fancy tree homework until C2 gives you trees.

When not to recurse in this course. Replacing a simple for over a flat list, to be clever, or on an input so large you will hit the recursion limit. Python's default is on the order of a thousand frames. Tail-call elimination is not a thing you should expect in Python. A loop is honest.

One more picture. Recursion is a stack of unfinished work, the same stack you will draw in C9. If you cannot name what is waiting to finish after the recursive call returns, you do not understand the function yet. Write that waiting work as one expression, not as a second algorithm hiding after the call.

Debugging. Print the arguments at the top of the function if you must, then take the prints out. Better, trace on paper for n=3. Better still, a test for the base case and a test for n=3 that you computed by hand.

Work

Exercises are listed so you can see the shape of the work. They are not assigned. Do not start them. No solutions on this site.

  1. Write fact(n) for n >= 0. Raise on negative. Tests for 0, 1, 5. No math.factorial in the body.
  2. Write sum_list(xs) recursively, empty list is 0. Then write the loop version. Keep the loop in production-shaped code. Keep the recursive one as the lesson artifact.
  3. On paper, trace fact(4) as a stack of frames. Bring the paper to chat.
  4. Write a function that returns the maximum number inside a nested list of numbers, [1, [2, 3], 0]. Recurse when you see a list. This is the interesting problem.
  5. Closed-resource. No AI. Do not paste a memoized Fibonacci essay. We are not there.
