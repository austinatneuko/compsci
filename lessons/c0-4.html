Git I

C0 Computing Environment

Locked. Because C0.3 Editor and terminal workflow is not mastered yet. You may read so the catalog is a real map. Do not start the exercises or the assigned reading until this lesson is current. Ratings do not move from a URL.

Objectives

  • Explain Git as a history of snapshots you chose, not as the save button for GitHub.
  • Create a repository, see status, stage, commit, and read a log.
  • Make a branch, switch, and see a diff.
  • Say what is in the working tree versus the last commit.
  • Keep secrets out of the first commit.

Teaching

Git is not GitHub. GitHub is a company that hosts Git repositories and adds a website. Git is a program that records a history of your project as a sequence of commits you chose to make. If you only ever click upload to GitHub, you have a backup with extra steps. If you can commit locally, read a diff, and say what changed, you have an instrument.

A repository is a directory with a hidden .git that stores that history. git init creates it. After that, every file is in one of a few states you must be able to name. Untracked, Git does not know it. Modified, Git knew an older version. Staged, you have marked these exact changes for the next snapshot. Committed, in history. git status is the map. People who skip status live in surprise. I will ask for status before I look at anything else.

A commit is not a save. Your editor already saved the bytes to disk. A commit is a checkpoint you are willing to talk about later. These files, this message, this parent. Good messages say why, not update. We will practice messages I would accept on a team. wip is a note to yourself, not a history. If your log is initial commit plus a dump, we redo it. I have no patience for a story that starts and ends in the same sentence.

The staging area exists because not every dirty file belongs in the next checkpoint. You will dislike it for a week and then need it. Stage on purpose. git add . is a blunt instrument. Use it when you mean everything here is the point, not because it is shorter.

Branches are names for commits. The poetic explanation, parallel universes, is fine. The mechanical one is better. A branch is a movable pointer. You make a branch before you experiment so main stays a place you can return to. git switch moves you. git diff shows the work. Merge and rebase wait for C4. Today you need create, switch, commit, look around.

What Git is not. Undo as a lifestyle. A substitute for backups of your whole machine. A place to put passwords. .env, keys, and anything that feels like a secret stay out. Once a secret is committed, assume it is burned, even if you later delete the file. History keeps the bytes. We will use .gitignore on day one for the obvious junk, editor swap files, __pycache__, OS dust.

You will make a first repository that is yours. Not a tutorial clone named my-first-repo following a blog's commit messages. A directory with a short README that says what it is, one or two files, a few commits that a stranger could read as a story. I will look at git log and git status. If the story is initial commit plus a dump, we redo it. Remote push comes after local history is real. Publishing is not the skill this lesson is for. History you can explain is.

Work

Exercises are listed so you can see the shape of the work. They are not assigned. Do not start them. No solutions on this site.

  1. Closed-resource. Install Git if needed, then git --version. In a new directory, git init. Create a README. status, add, commit. Change the README. diff. Commit again. log. Paste nothing into chat yet. Be ready to show me the log in a session.
  2. Create a branch. Switch to it. Add a file. Commit. Switch back to the original branch. Say in chat, without looking at notes, where that new file went and how you would get it back.
  3. Add a .gitignore that excludes at least one real junk pattern on your machine. Commit it. Prove with status that a junk file is untracked on purpose.
  4. Do not push to GitHub until I say. Do not commit a secret. Do not use git add . blindly if you cannot name what it will include.
