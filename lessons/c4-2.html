ADTs and representation independence

C4 Software Construction

Locked. Because the prerequisite course is not mastered. You are on C0.1. You may read so the catalog is a real map. Do not start the exercises or the assigned reading until this lesson is current. Ratings do not move from a URL.

Objectives

  • Define an ADT as operations plus contracts, independent of the representation.
  • Hide the representation. Catch a leak: a method that returns the internal list.
  • Swap a representation without changing tests that honor the spec.
  • State representation independence in one paragraph that is not wrong.

Teaching

An abstract data type is the C2 idea with manners. Clients see operations and contracts. They do not see whether the stack is a list or a linked list. Representation independence is the name. You should be able to change the guts without rewriting the callers, as long as the contracts hold.

A leak looks like return self._xs when _xs is the internal list. The caller now mutates your representation. The invariant is decorative. The client now owns your invariant. Return a copy, or return an iterator, or do not return the collection. Whatever the spec said. Returning a copy, or not returning the collection, is a decision in the spec, not a style preference you add after I catch you.

You will implement one ADT twice, array stack and linked stack, against one test file. The tests do not import the representation. That is the whole exercise. If the tests have to change, you failed the independence, not the syntax. If the tests import a private name, the independence was theater.

This is also how you will treat files, HTTP clients, and databases later: behind an interface you can fake in a test. C4 is where that habit starts, on stacks, not on cloud vendors. P1 will need this seam. If you learn it on a stack, you will have it when the object is a row.

Find the leak in a class I give you. Write the failing test that proves the leak, then fix. A paragraph in chat: what a client may assume, what it may not. If that paragraph is the implementation, we rewrite it.

C4 is the course where other people have to live with your code. Specs, ADTs, tests, PR-quality Git, review, a debugging method, API-shaped errors, a little FP taste, and AI evaluation as law. MIT 6.1020 is the gold statement of the ideas; we do the work in Python. Google engineering practices are a baseline, not scripture. Dual-track work starts here: closed first, then catch the model. If you treat this course as a checklist of tools, you will still write a 400-line main. If you treat it as contracts plus history plus review, P1 becomes possible.

Representation independence fails the moment you return the internal list. The client now owns your invariant. Returning a copy, or not returning the collection, is a decision in the spec. Two representations against one test file is the proof. If the tests import a private name, the independence was theater.
