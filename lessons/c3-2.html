Sets, functions, relations

C3 Discrete Mathematics

Locked. Until Gate A. Systems depth and remaining CS wait until you can apply. You may read so the catalog is a real map. Do not start the exercises or the assigned reading until this lesson is current. Ratings do not move from a URL.

Objectives

  • Use set notation and the usual operations without waving.
  • Define a function as a mapping with a domain and codomain, and say if it is injective/surjective.
  • Treat a relation as a set of pairs; know reflexive/symmetric/transitive as checks.
  • Connect this to types and to "is this a well-defined mapping."

Teaching

Sets are how we name collections without pretending they are lists. Union, intersection, complement, product. You will compute small ones and write one inclusion proof: A ⊆ B means every x in A is in B. Empty-set edge cases are not cute; they are where people fail induction later.

A function is a relation with a uniqueness property: each input in the domain has exactly one output. Injection and surjection will return in counting and in "can I invert this." In programming, a function that maps two users to the same id is a failed injection you shipped.

Equivalence relations partition a set. "Same remainder mod n" is the example we will keep. You will check the three properties, not recite them.

Injection and surjection return when you ask whether a mapping is reversible. An equivalence relation partitions. Empty-set edges are where induction later dies. One inclusion proof is required: every x in A is in B, not a picture of circles you did not argue.

Discrete math in this program is CS 70 style: math you will use on programs and algorithms, not a symbol museum. Junior loops do not test proofs. That is why we deferred this past the gate. It is still the program. We did not delete CS. We reordered it.

Proofs are written so I can see the claim, the setup, the argument, and the close. Examples are not a proof. A symbol pile is not a proof. Oral defense is how I catch a fluent fake. A model will give you a fluent fake. Closed.

Discrete math is deferred because junior loops do not test proofs, not because proofs are optional for a complete engineer. Logic, sets, induction, counting, graphs, modular arithmetic, and proofs you will use on programs. You will prove a loop invariant on code you wrote in C2, prove a simple graph claim, and refute a wrong induction. No coding-heavy work. A fluent fake proof is a fail when I poke a hole. This course feeds C5-remainder and C12. If a loop exposes the hole during search, we schedule it sooner. We do not lower the gate.
