C14 Security Fundamentals

Locked. Until Gate A. Systems depth and remaining CS wait until you can apply. You may read so the catalog is a real map. Do not start the exercises or the assigned reading until this lesson is current. Ratings do not move from a URL.

Objectives

  • Go deeper than C8: sessions versus tokens, refresh, revocation, OAuth as delegated access.
  • Authorize on every request for the resource, not once at login.
  • Know identifier versus access token as vocabulary if we touch OIDC.
  • Do not add OAuth to a small app as fashion.

Teaching

C8 shipped authentication. C14 asks you to defend it against a sharper story: a stolen refresh token, a redirect you did not mean, an object id you treated as a capability. Every request authorizes. Caching 'this user is admin' without a story is a bug. UUIDs are not permission.

OAuth and OIDC as a read: you are delegating. If we do not need it, we do not add it. Fashionable authentication is a threat-model smell.

Security after the gate is a threat model, primitives as contracts, classes of web failure as broken boundaries, secrets and supply chain, a sharper look at auth, and a PR review exam. You will not invent crypto. You will not touch systems you do not own. The exit is a model of a feature, two real bugs in a PR, and a TLS paragraph that is not wrong. C8 was the checklist. This is the defense.

Every request authorizes. An identifier is not permission. Refresh and revocation are part of the story. Delegated access is a dance you add only if you need it. Fashionable authentication is a threat-model smell. Sharper checklist on P1.

Stay on what we own. Model first. Primitive as a contract. Boundary as a class of failure. Secret as burned once committed. Authz on every request. Review as if a user were the asset. The exam is that packet. I will not put exploits on this site. You will not go looking for them on systems that are not the lab.
