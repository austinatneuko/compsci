The Shell

Definitions

terminal
The window program that draws text and sends your keystrokes.
shell
The program inside the terminal that reads a line and starts other programs.
prompt
The text the shell prints when it is waiting for you to type.
command
The first word you type. The name of the program the shell should start.
argument
A word after the command that the program receives.
working directory
The folder the shell treats as here right now.
PATH
A list of folders the shell searches when you type a program name.

Diagram

You  -->  Terminal window  -->  Shell  -->  Program  -->  text back

You type in a window. The shell reads the line. A program runs. Text comes back.

What a shell is

A computer runs programs. A program is a file. You start it, it does work, it prints text, it exits.

The desktop is a short list of buttons. If the job is not on the list, you cannot name it. A shell is a program that starts other programs by name. You type the name. The shell finds the file, starts it, and shows you the text that came back.

I still work this way on a Mac that has a perfectly good desktop. Text composes. The output of one program is text, and the next program will take text. The same interface works on your laptop and on a machine with no mouse and no screen.

Do this now

Open Terminal. Do not type yet. Look at the line that is waiting.

You should see a blinking cursor after a short line of text. That line is the prompt.

Open one on a Mac

On your Mac, press Command-Space. Type Terminal. Press return.

You can also open Finder, then Applications, then Utilities, then Terminal. Keep it in the Dock. You will use it every day in this program.

The window that opens is the Terminal app. The program inside it is usually zsh. zsh is a shell. The window and the shell are not the same thing. If the window is fine and the shell is stuck, you now know which one to blame.

Do this now

Press Command-Space, type Terminal, press return.

A window opens. A line ends in % or $ and a cursor sits after it.

The prompt

The shell prints a prompt when it wants a line from you. On a Mac it often looks like you@Mac ~ %. The ~ means your home folder. The % means you are not the root user.

The prompt is not a command. It is the shell saying it is ready. You type a line. You press return. A program runs, or the shell tells you it could not find that name. Then another prompt.

Do this now

Look at your prompt. Write down the exact text before the cursor. Do not add extra spaces.

You should be able to point at the machine name, the ~ or folder, and the % or $.

date and echo

The first word you type is the command. Words after it are arguments.

date is a program that prints the current date and time. echo prints its arguments back to you. echo hello starts echo with one argument. echo hello world starts echo with two.

If a name has a space, wrap it in straight quotes: echo "hello world".

Do this now

date
echo hello
echo "hello world"

You should see a date line, then hello, then hello world. Then a new prompt.

man

man is short for manual. man date opens the manual page for date. On a Mac the text opens in a pager. Space moves down. q quits.

You do not memorize every flag. You look them up. If man says there is no manual, try the program with --help.

Do this now

man echo

A manual page opens. Find one sentence that says what echo does. Press q. You should be back at the prompt.

cd and pwd

pwd prints the working directory. That is the folder the shell treats as here.

cd changes the working directory. cd /tmp moves you to /tmp. cd ~ moves you home. cd with no argument also moves you home.

cd is built into the shell. It is not a separate program. which cd will say it cannot find a file named cd. That is expected.

Do this now

pwd
cd /tmp
pwd
cd ~
pwd

The first and last paths should be your home. The middle path should be /tmp.

Absolute vs relative paths

An absolute path starts with /. It names the walk from the root of the disk. /tmp and /Users/you are absolute.

A relative path does not start with /. It starts from the working directory. If you are in /Users/you and you type cd Documents, the shell looks for /Users/you/Documents.

Beginners fight the machine because they type a name that exists, but not here. The file is real. Your address is wrong.

Do this now

cd /
pwd
cd tmp
pwd
cd ~

After cd tmp you should be in /tmp. You got there with a relative path.

. and ..

Every folder has two special names. . means this folder. .. means the parent folder.

cd . does nothing useful. cd .. walks up one level. cd ../.. walks up two. You can mix them: cd /tmp/../tmp lands in /tmp.

Do this now

cd ~
pwd
cd ..
pwd
cd ~

The middle path should be the parent of your home, usually /Users.

PATH and which

When you type date, the shell has to find a file named date. It looks in a list of folders stored in PATH. The folders are separated by :. The first match wins.

echo $PATH prints that list. which date prints the file the shell will run for the name date. You can also start a program by its full path and skip PATH: /bin/date.

If the shell says command not found, it searched PATH and missed. The program may still live on the disk. You gave the wrong name, or PATH is missing a folder.

Do this now

echo $PATH
which date
/bin/date

which should print a path such as /bin/date. The last line should print the date.
