Stacks/queues

C2-lite Data Structures (pre-gate)

Locked. Because the prerequisite course is not mastered. You are on C0.1. You may read so the catalog is a real map. Do not start the exercises or the assigned reading until this lesson is current. Ratings do not move from a URL.

Objectives

  • Implement a stack and a queue on top of a structure you choose and can justify.
  • State LIFO and FIFO in operations, not in slogans.
  • Use a stack for a small real job (matching delimiters or undo).
  • Know why a list-as-queue with pop(0) is a cost bug.

Teaching

A stack is LIFO: the last value you pushed is the next you pop. A queue is FIFO: the first value you enqueued is the next you dequeue. Those are contracts. The structure underneath is your choice, with a bill. A Python list is a fine stack (append / pop). The same list is a bad queue if you pop(0) — that is linear, every time, because the array shifts.

You may implement a queue with a linked list (head and tail) or with a ring in an array, or with collections.deque after you have implemented one of the first two. Using deque without ever writing a queue is how people arrive at interviews with a brand name and no picture.

These two ADTs show up everywhere later: function call stacks (you already traced them), BFS (C5-lite), undo, work lists, printing tasks. I care that you can implement, test, and pick. I do not care that you memorized a cartoon of plates.

Error policy is part of the ADT: pop on empty raises, or returns None, and the docstring says which. Silent None is how bugs move in time. Raise unless I say otherwise.

C2-lite is judgment plus implementation, not a museum of types. A structure is the operations you need and the bill they send when n grows. You already use lists and dicts; now you must be able to build the ones a junior actually needs and say when a list beats a hash. Heaps and graphs-as-ADTs wait until after the gate. That is not because they are optional forever. It is because the hiring bar uses lists, hashes, and trees, and we will not pretend you implemented a heap if we did not sit with one. Every module ends with costs you can say out loud.

Stacks and queues are tiny contracts that show up inside parsers, undo, BFS, and the call stack you already traced. The backing structure is a cost decision you can change if the ADT holds. Using pop(0) as a queue is the first time a familiar list becomes the wrong machine. Write the benchmark. Keep the number. You will need it when someone says Python is slow and the truth is the shift.

Work

Exercises are listed so you can see the shape of the work. They are not assigned. Do not start them. No solutions on this site.

  1. Implement Stack and Queue with tests for empty operations.
  2. Write matched(s) that uses a stack to check (), [], {} balance. Tests include a fail case.
  3. Benchmark list-pop(0) queue vs your queue on large n. Write the result in a comment or a small note.
  4. Closed-resource. Timed quiz: which structure, which cost.
