Objectives

  • Write a GitHub Actions workflow that installs, tests, and fails on red.
  • Treat CI as the gate to submit: if it is red, you are not done.
  • Do not store secrets in the workflow file.
  • Read a red log without pasting it into a model first.

Teaching

CI is a machine that runs your tests on every push the way I would run them. GitHub Actions is the default here. A workflow is YAML that says: on push, use this OS, install, pytest or vitest, exit nonzero on fail. You will read the YAML. You will not treat it as a badge generator. CI is a machine that runs your tests the way I would. Red means you are not done.

Secrets live in the host's secret store. A key in the YAML or in the repo is a burned key. We practice with dummy secrets first. Secrets are not in the workflow file.

A red CI you fix by skipping the test is visible in the diff. Don't. A red CI you fix by pinning a version you understand is engineering. Skip a test to go green and I will see the diff. Read a red log before you ask a model.
