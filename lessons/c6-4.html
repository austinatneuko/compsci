SQL I

C6 Backend Systems

Objectives

  • Write SELECT, WHERE, JOIN inner, INSERT, UPDATE, DELETE.
  • Treat SQL as a language you type, not as an ORM log you peek at.
  • Predict the result of a join on a six-row example by hand.
  • Keep SQL injection in mind: parameters, never string-paste of user input.

Teaching

SQL is the interface to the relational model. You will write it by hand before any ORM generates it. SELECT names the columns, or the stars, which we will stop using in APIs. WHERE filters. JOIN connects tables on a predicate, usually keys. INSERT, UPDATE, DELETE change the facts. Transactions wait for C6.7. Today each statement is its own little world unless I say otherwise.

A join is not combine two spreadsheets in your head until it looks right. It is a Cartesian product filtered by the ON clause, or an equivalent picture you can draw. I will sit you in front of six rows and you will write the result table before you run it. Predict six rows on paper before you run. SELECT star in an API is how you leak a column you added later.

Parameters: WHERE id = %s with a bound value. Never f-string a user id into SQL. Injection is not an advanced topic. It is a first-week topic that C8 and C14 will return to. Today you form the habit. Parameters are not optional politeness. They are the first injection defense.

Postgres is the default database. You will run it locally. Docker later if we need it. Native is fine. The tutorial I assign is not optional wandering. The SQL exam later is closed. If you have been generating SQL with a model, that exam will show it.

Fifteen queries on a course database I provide, including a join you predict on paper. One insert, update, delete path with parameters. Closed-resource. No AI on the drills.

Backend work in this program is HTTP plus a relational database plus a thin framework, in that order. FastAPI is not the syllabus. If you cannot read a raw request, predict a join, or justify an index, a green OpenAPI page is decoration. We talk to Postgres with parameters before any ORM. Transactions are how two writes become one fact. Validation dies at the edge with a 4xx that names the field. The service you build here is the skeleton of P1. Dishonest schemas get rejected until they are honest. That loop is the course.

A join is a product filtered by a predicate. Predict six rows on paper before you run. Parameters are not optional politeness. They are the first injection defense and a habit C8 and C14 will assume. SELECT star in an API is how you leak a column you added later.
