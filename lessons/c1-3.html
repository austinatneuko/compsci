Functions and scope

C1 Programming Fundamentals in Python

Locked. Because C0 module 3, editor and terminal workflow, is not mastered yet. C1 can start in parallel only after that. You may read so the catalog is a real map. Do not start the exercises or the assigned reading until this lesson is current. Ratings do not move from a URL.

Objectives

  • Write a function that takes arguments and returns a value, not one that only prints.
  • Explain scope. A name inside the function is not the name outside, even if it looks the same.
  • Say what happens to objects passed in. Rebinding a parameter is local. Mutating a mutable object is not.
  • Read a traceback that names your function and jump to that line.
  • Keep functions small enough to explain in one breath.

Teaching

A function is a named piece of computation with inputs and an output. You define it once. You call it whenever that computation is the next thing you need. If you are copying the same six lines, you are late to this lesson.

def creates the function object and binds it to a name. The body does not run at definition time, except in the ways we will not use yet. A call f(3) binds the parameter names to the argument objects and runs the body. return hands a value back to the caller and stops the function. If you omit return, the function still returns. It returns None. That is why a function that only prints is a dead end for testing and composition. Print is a side effect for humans. Return is how programs talk to themselves.

Parameters are names local to the call. Assigning to a parameter rebinds that local name. It does not rebind the caller's name. This is the same picture as C1.1, now inside a call. The twist. If the object is mutable and you mutate it, append to a list, set a key on a dict, the caller sees the mutation, because you did not rebind. You changed the object both names refer to. I will put this on the exam. Draw it.

Scope in C1 is local versus global. A name assigned in the function is local unless you do something exotic, which you will not. Reading a global is legal and usually a smell. Writing a global with global is a smell I will reject. Pass values in. Return values out. Hidden state is how a 40-line homework becomes undebuggable.

Docstrings start now. One sentence under the def that says what the function returns given what. Not a novel. Not this function does stuff. We will turn these into contracts in C4. Today they are how you notice you cannot state the job.

Tracebacks are a gift. Read from the bottom. Exception type and message. Then the last stack frame that is your file. File, line, function. Go there. Do not start at the top of a library path you did not write. Do not paste the traceback into a model in this course until I say AI-open.

Size. If I ask what the function does and you need a paragraph, it is two functions. Helpers are free. Nested helpers we will mostly avoid until you can explain closures, which is not this week.

Default arguments exist. Do not use a mutable default, def f(xs=[]). That bug is famous because it is real. If you need a default empty list, use None and create a list in the body. I will deduct for the famous bug after I have warned you, which is now.

Work

Exercises are listed so you can see the shape of the work. They are not assigned. Do not start them. No solutions on this site.

  1. Write absolute(n) that returns the absolute value without calling abs. Print is not allowed inside it. Write three calls that print the results from the outside.
  2. On paper, def f(x): x = x + 1; return x then n = 4; m = f(n). What are n and m? Then the list version, def g(xs): xs.append(1) called on a = [0]. What is a? Draw the names.
  3. Trigger a TypeError or ValueError inside a two-function call chain. Read the traceback out loud in chat. Which function, which line, which message.
  4. Take a 20-line script from C1.2 and extract at least two functions that return values. Run it. Commit.
  5. Closed-resource. No AI. No global.
