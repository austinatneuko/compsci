Storage and pages

C13 Databases as Systems

Locked. Until Gate A. Systems depth and remaining CS wait until you can apply. You may read so the catalog is a real map. Do not start the exercises or the assigned reading until this lesson is current. Ratings do not move from a URL.

Objectives

  • Explain a page/block as the unit the database moves.
  • Connect to C9/C10 I/O: the DB is a program with a file.
  • Know that a row is not a file.
  • Read DDIA ch.1–2 as assigned, not as a poster.

Teaching

C6 taught SQL as a user. C13 treats the database as a system: storage, indexes as structures (C2), plans, isolation, a preview of replication. A table lives in pages on disk (and in cache). The engine reads pages, not “a row from the cloud.”

DDIA chapters 1–4 are the primary prose. Postgres EXPLAIN and CS 186 lectures selected are the lab. You will not build Postgres.

Databases as systems is storage, indexes as structures you already implemented, plans you can read, isolation you can break, a preview of copies and splits, and constraints as the last line of integrity. C6 taught SQL as a user. This course treats Postgres as a program with a file and a planner. DDIA early chapters plus EXPLAIN. The exit is a slow query you fix and an isolation bug you can name in an API.

The engine reads pages, not a row from a cloud. A table is a file plus a cache plus a crash story. Write-ahead logging as a preview: why a mid-write crash needs a log. You will not build the engine. You will stop talking as if SQL were physics.

The planner is an optimizer with estimates that can be wrong. Your job is to read the plan and change the query, the index, or the schema, and say what happened. Isolation is a story about two requests, not a level name you recited. Constraints remain the last line when the app is wrong. Document stores get an honest sentence, not a brand preference.
