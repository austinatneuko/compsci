DP depth

C5-remainder Algorithms I (remainder)

Locked. Until Gate A. Systems depth and remaining CS wait until you can apply. You may read so the catalog is a real map. Do not start the exercises or the assigned reading until this lesson is current. Ratings do not move from a URL.

Objectives

  • Define a DP state that is not "the answer."
  • Write a recurrence, base, and fill order, or memo.
  • Implement one harder DP than C5-lite, knapsack, LCS, or I pick.
  • Know when DP is hopeless, state space too big. a preview of NP.

Teaching

DP depth is the same four words, state, recurrence, base, order, on a state you would not have invented in week two. We will fight the urge to store the entire solution path in the state when an index plus a remaining capacity was enough.

Implementation with tests on small fixtures you can compute by hand. If the table is wrong, the hand fixture finds it. If you only test the leetcode sample, you will ship a table off-by-one.

State is an index plus a remaining capacity, or a pair of positions, not the entire path. Hand fixtures find off-by-one tables. Leetcode samples alone will not. Invent a state for a cousin problem. If the table does not fit, that is the NP preview.

C5-lite taught you to narrate a medium. This course teaches you to classify a new problem, implement when it is the kind we solve, state complexity, and say whether a polynomial exact algorithm is likely. If it is not, you name an alternative: restrict, approximate, or exponential on small n. That sentence is engineering, not a meme about hardness.

Remainder is also a stop rule. Some problems do not have a clever polynomial exact algorithm you are going to invent on a Tuesday. Implementations still have tests. Proofs still have structure. Conceptual exam on NP catches slogans.
