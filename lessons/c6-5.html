SQL II and indexes

C6 Backend Systems

Locked. Because the prerequisite course is not mastered. You are on C0.1. You may read so the catalog is a real map. Do not start the exercises or the assigned reading until this lesson is current. Ratings do not move from a URL.

Objectives

  • Write GROUP BY and an aggregate you can explain.
  • Read a simple EXPLAIN enough to see a seq scan vs an index scan.
  • Propose one index and say which query it is for.
  • Know that an index is a data structure with a write cost.

Teaching

GROUP BY partitions rows and lets you count, sum, average per group. HAVING filters groups. If you write GROUP BY and SELECT a column that is neither grouped nor aggregated, Postgres is right to complain. We will get that error on purpose. GROUP BY is a partition plus an aggregate.

An index is a structure, B-tree by default in Postgres, that makes some lookups and ranges cheap at the cost of space and slower writes. It is not a magic make it fast button. Use The Index, Luke exists because people add indexes they cannot justify and miss the one they need. An index is a structure with a write cost.

EXPLAIN, and EXPLAIN ANALYZE carefully, is how you see the plan. I do not need you to recite every node type. I need seq scan vs index scan, and a sentence about rows. C13 goes deeper. Today is literacy, not a DBA career.

You will justify an index from a query, not from a feeling. id is a primary key already has an index. Adding twelve more because a blog said so is not design. Propose one index for one query. Show EXPLAIN before and after on the query it was for. Two sentences.

Write five grouped queries on the course database. Closed-resource SQL quiz. No AI. Primary keys already have one.

Backend work in this program is HTTP plus a relational database plus a thin framework, in that order. FastAPI is not the syllabus. If you cannot read a raw request, predict a join, or justify an index, a green OpenAPI page is decoration. We talk to Postgres with parameters before any ORM. Transactions are how two writes become one fact. Validation dies at the edge with a 4xx that names the field. The service you build here is the skeleton of P1. Dishonest schemas get rejected until they are honest. That loop is the course.
