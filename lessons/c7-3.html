DOM and the browser

C7 Frontend Systems (TypeScript + React)

Locked. Because the prerequisite course is not mastered. You are on C0.1. You may read so the catalog is a real map. Do not start the exercises or the assigned reading until this lesson is current. Ratings do not move from a URL.

Objectives

  • Explain the DOM as a tree the browser keeps, not as HTML.
  • Query, create, and update nodes in vanilla TypeScript.
  • Listen for an event and update state without a framework.
  • Know that React will be a library over this, not a replacement universe.

Teaching

The browser parsed HTML into a tree of nodes: the Document Object Model. JavaScript, and TypeScript, can walk that tree, change it, and listen for events: click, submit, input. If you skip this and jump to React, you will treat the framework as physics. It is not. The DOM is the tree. React will be a library over it. If you skip this, the framework becomes physics.

You will build a small UI with no React: a list, a form, a status message. You will keep state in a variable, render by updating the tree or rebuilding a region, and not leak listeners in a loop. It will feel clumsy. That clumsiness is the lesson. The clumsiness of a vanilla UI is the lesson. We rebuild it next.

Accessibility starts here: labels for inputs, buttons that are buttons, focus not trapped. We are not becoming designers. We are not shipping icon-only controls with no name. Labels, real buttons, no icon-only controls with no name.

The rebuild in this course is vanilla, then React, then against your API. This module is the first third. The three rebuilds are the spine. Each time the job is the same so the library cannot hide.

Frontend work is TypeScript as a language, the DOM as a tree, React as a view layer, and then your API. We rebuild a small UI three times so the library cannot become physics.
