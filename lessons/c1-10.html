Objectives

  • Specify a small program in a paragraph before you write it.
  • Implement 80 to 150 lines you designed. Functions, tests, a README that runs.
  • Trace a 50-line function you did not write, on paper.
  • Sit a closed-resource coding exam without a model, notes as I allow.
  • Know what P0 will ask next, and what this course's exit actually is.

Teaching

This module is not a new construct. It is the bill. C1's exit is this. Independently write, test, and explain an 80 to 150 line program that you designed, and trace someone else's 50-line function on paper, with no AI on the exam. Everything else was inventory.

Designed means you wrote a short spec first. Who the user is, what the input is, what success looks like, what you will refuse to handle. A spec that says it does stuff with files is not a spec. A spec that says reads a UTF-8 log of timestamped events, one per line, and writes a count per hour is a spec. I approve the spec before you disappear for a week. That is also how P0 will work, with a stricter review.

Eighty to a hundred fifty lines is a size you can still hold. If you are at 300, you have either the wrong problem or a missing decomposition. If you are at 40 and the program is a script of prints, you have not designed. You have doodled. Lines are not a virtue. Completeness against the spec is.

Tests are part of the artifact. A README that says how I run the program and the tests is part of the artifact. A Git history is part of the artifact. A single file dumped the night before with a tutorial's variable names is a fail even if it runs.

The paper trace is a separate skill and we will practice it on my code, not only yours. I will sit with you and watch the table of names. You may not run it in your head as a vibe. You update the table. This is how I know the midterm was not a fluke.

The closed-resource exam is timed enough to be real and not sadistic. You will write functions you have written cousins of. You will not have Stack Overflow. You will not have a model. You will have the language you practiced. If that sentence makes you want to grind 40 more exercises, good. The exercises exist. I will assign them.

P0, next, is a command-line tool you specify yourself, not a tutorial clone, with a review. C1 is the language. P0 is the first thing a stranger is supposed to run. Do not start P0 during this module unless I say C1 is close enough and the spec is honest.

If a skill from C1.1 through C1.9 is shaky, we remediate now. Weakness in an earlier concept pauses forward motion. That is not a punishment. That is the program refusing to lie about what you can do.

Work

Exercises are listed so you can see the shape of the work. They are not assigned. Do not start them. No solutions on this site.

  1. Write a one-paragraph spec for your C1 mini-project. Wait for my yes. Then implement, test, README, Git.
  2. Closed-resource exam when I schedule it. Write and explain. No AI. Paper nearby for the trace.
  3. I will hand you a 50-line function. Trace it on paper. We will not start that drill on the exam day for the first time.
  4. 40+ exercises should already be mostly done by now. This module is for the holes and the project, not for discovering loops exist.
  5. Do not submit a tutorial clone. Do not submit a program you cannot explain line by line.
