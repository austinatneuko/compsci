Cost model and arrays

C2-lite Data Structures (pre-gate)

Locked. Because the prerequisite course is not mastered. You are on C0.1. You may read so the catalog is a real map. Do not start the exercises or the assigned reading until this lesson is current. Ratings do not move from a URL.

Objectives

  • State a cost model: time and memory in terms of n, not 'fast on my laptop'.
  • Implement a static array picture and a dynamic array (Python list as amortized array).
  • Explain why append is usually cheap and why insert-at-front is not.
  • Use big-O as a sentence you can say, not as decoration on a slide.

Teaching

A data structure is a way to store values plus the costs of the operations you actually run. If you cannot name the operations — get by index, append, insert at i, scan — you do not have a structure, you have a pile. This course makes you implement the piles juniors actually use, and state the bill.

An array (in the machine sense) is a contiguous block: index i is arithmetic, not a walk. That is why a[i] is constant time in the model we will use. Python’s list is a dynamic array: it over-allocates, so most appends write into spare room (cheap) and some appends copy the whole block into a bigger one (expensive, rare). Amortized constant append is the phrase. Insert at the front is linear because everything else moves. If that sentence is not boring by the end of the week, we stay here.

The cost model is not a personality quiz about which company invented big-O. For a given operation, how does the work grow when the collection grows? Constant, logarithmic, linear, linearithmic, quadratic. I want those words used about your code. “It ran fine” is not a cost.

You will implement a small dynamic array in Python (a class that holds a list and a size, with an explicit grow) so the over-allocation is your code, not a rumor about CPython. Then you will use the built-in list like a professional, with the picture in your head.

C2-lite is judgment plus implementation, not a museum of types. A structure is the operations you need and the bill they send when n grows. You already use lists and dicts; now you must be able to build the ones a junior actually needs and say when a list beats a hash. Heaps and graphs-as-ADTs wait until after the gate. That is not because they are optional forever. It is because the hiring bar uses lists, hashes, and trees, and we will not pretend you implemented a heap if we did not sit with one. Every module ends with costs you can say out loud.

Amortized analysis is the first time a cost and a single operation disagree. One append copies the world; most appends do not. If you only time n=10 you will believe insert-at-front is fine. If you only recite O(1) you will be surprised in an interview when they ask about the copy. Draw the array before and after a grow. That drawing is the lesson, not the class wrapper.

Work

Exercises are listed so you can see the shape of the work. They are not assigned. Do not start them. No solutions on this site.

  1. Implement DynArray with get, set, append, insert, pop. Tests for grow. Closed-resource.
  2. Time (even crudely) append-at-end vs insert-at-0 for n = 10_000. Write the numbers and the explanation.
  3. State, without notes, the cost of index, append (amortized), insert at i.
  4. No AI. Timed quiz on costs.
