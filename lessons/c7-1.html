Objectives

  • Treat TypeScript as a language. Types are not optional comments.
  • Write functions with typed parameters and return types.
  • Explain why any is a surrender.
  • Read a type error and go to the line, like a Python traceback.

Teaching

TypeScript is JavaScript plus a type system that is erased at runtime. That last clause matters. The compiler is a proof assistant for a large class of bugs, not a bodyguard at runtime. You still validate at the HTTP edge. You still do not trust the network. Types are erased at runtime. The checker is a proof assistant, not a bodyguard on the network.

We start with types on functions, literals, unions such as ok or err, and arrays. You will not turn the checker off. any is banned in course code unless I grant a one-line exception you comment. any is a surrender. as casts are a smell. We will use them when a boundary forces it and we will name the boundary.

The Handbook is the text, selected pages. No YouTube tour of TS in 15 minutes. You will read errors. The errors are good if you let them be. A type error is a traceback: go to the line.

This is the second language in the program. Transfer what you know: values, names, functions, tests. vitest later. Syntax is the cheap part. Honesty of types is the expensive part. Handbook pages I assign, not a fifteen-minute tour.

Frontend work is TypeScript as a language, the DOM as a tree, React as a view layer, and then your API. We rebuild a small UI three times so the library cannot become physics. Types stay honest: unions for states, no any, no data while loading. Forms have labels and errors a keyboard can reach. The exit is brownfield: add a feature to an app you have not seen. Tutorial-hell YouTube is excluded on purpose. Official docs, selected pages. If you cannot read a file you did not write, you are not done, even if your greenfield demo looks pretty.
