Editor and terminal workflow

C0 Computing Environment

Locked. Because C0.2 Filesystem and permissions is not mastered yet. You may read so the catalog is a real map. Do not start the exercises or the assigned reading until this lesson is current. Ratings do not move from a URL.

Objectives

  • Separate the terminal (a window) from the shell (a program) from the editor (where you change files).
  • Edit a file without leaving a keyboard workflow: open, change, save, return to the prompt.
  • Survive the first hour of a real editor — vim, nano, or VS Code’s integrated terminal — without rage-quitting.
  • Run a program you just edited and look at the error in the same place you type.
  • Choose one editor and stay with it through C0. Tourism is not a workflow.

Teaching

Three programs are about to share one rectangle on your screen, and beginners mash them into one idea called “the terminal.” They are not one idea. The terminal emulator is a window that draws text and sends keystrokes. The shell is the program usually running inside it, waiting for a line. The editor is a different program that takes over that window, or a neighboring one, so you can change the bytes in a file. When you are “stuck in vim,” you did not break Linux. You entered a program that uses the keyboard differently from the shell, and you have not yet learned how to leave.

Why this lesson exists before Python: every later course assumes you can change a file, run it, read the failure, change it again, and keep a trail. If that loop requires a mouse, a different app, a cloud pastebin, and a prayer, you will avoid it. Avoiding the loop is how people stay beginners.

You may use VS Code. Many professionals do. I do not care about the brand. I care that you can (1) open a folder that is a project, (2) edit a file as text, (3) run a command in an integrated or adjacent terminal against that same folder, and (4) see the file that failed. If your editor cannot do that, it is a notepad, not a workspace.

I also want you to be able to edit on a machine that has no VS Code — a server, a container, a recovery shell. That means at least one terminal editor. nano is honest and small. vim is everywhere and hostile for an hour. I will not romanticize vim. I will make sure you can open, change, save, and quit, because someday the only editor on the box will be vi. The keystrokes are a tax. Pay it once.

Workflow is a habit, not a plugin list. You work in a directory that is the project. You do not spray files across Desktop. You keep the terminal pointed at that directory. You run the program from there so relative paths mean what you think. You read the traceback from the top: file, line, message. Then you go to that line on purpose, not by scrolling until something looks familiar.

Copy and paste from the web into an editor will waste a day of C1 if you do not also look at what you pasted. Invisible characters, smart quotes, and mixed tabs are not theoretical. We will set the editor to show whitespace and to use spaces. That is not aesthetics. That is so Python and Git see the same file you think you see.

This lesson is also about attention. An editor with twenty extensions, a theme marketplace, and AI autocomplete on day three is a carnival. We will add tools when a job requires them. For C0, the job is: change a file, run a command, read the result, repeat without breaking the chain.

Work

Exercises are listed so you can see the shape of the work. They are not assigned. Do not start them. No solutions on this site.

  1. Pick one GUI editor (VS Code or equivalent) and one terminal editor (nano or vim). Write the names in chat so I know which pair you own.
  2. Closed-resource: in the terminal editor, create a file named notes.txt in a disposable directory. Write three lines. Save. Quit. cat the file from the shell. If you cannot quit, that is the assignment — learn the exit, do not force-kill the window.
  3. In your GUI editor, open that same directory. Change one line. Save. Back in the terminal, cat again. Confirm you are looking at one tree, not two copies.
  4. Without a mouse if you can: switch from editor to terminal, run ls, switch back. Time yourself. The number does not matter. The loop does.
  5. Do not install a vim config from the internet. Do not install twenty VS Code extensions. If AI autocomplete is on, turn it off for C0.

Mastery

You can open, change, save, and leave a terminal editor without panic. You can edit a project file and run a command against the same directory. You can point at the line an error named. Ratings move when I watch the loop, not when the page is open.
