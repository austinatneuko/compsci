Definitions

terminal emulator
The window program that draws text and sends keystrokes.
shell
The program usually waiting inside that window for a line.
editor
A different program that changes the bytes in a file.
buffer
The text you are editing before it is written back to disk.
save
Write the buffer to the file on disk.
working folder
The project directory the editor and the shell should share.
whitespace
Spaces, tabs, and newlines. They are real characters.

Diagram

one project folder
├── notes.txt     you edit this
└── $ prompt      you run commands here

Terminal window ── shell

Same folder. Same files. Two programs.

If the editor has one copy and the shell has another, you will debug a ghost.

Three programs, one rectangle

Beginners mash three programs into one word: the terminal. They are not one idea. The terminal emulator is a window. The shell is the program waiting for a line. The editor is a different program that takes over that window, or a neighboring one, so you can change a file.

When you are stuck in vim, you did not break macOS. You entered a program that uses the keyboard differently from the shell, and you have not yet learned how to leave.

Do this now

Say out loud, before you type: window, shell, editor. Point at each when they appear.

You can point at the Terminal window, the prompt inside it, and later the editor. Three names.

Why this lesson is before Python

Every later course assumes you can change a file, run it, read the failure, change it again, and keep a trail. If that loop needs a mouse, a different app, and a pastebin, you will avoid it. Avoiding the loop is how people stay beginners.

I have no interest in a student who can recite syntax and cannot save a file on a box with no desktop.

Do this now

pwd
mkdir -p /tmp/c0-3
cd /tmp/c0-3
pwd

You are in a disposable folder. All work in this chapter stays here.

A terminal editor

You may use VS Code. I do not care about the brand. I also want you able to edit on a machine that has no VS Code. A server. A container. A recovery shell.

nano is honest and small. vim is everywhere and hostile for an hour. I will not romanticize vim. I will make sure you can open, change, save, and quit, because someday the only editor on the box will be vi.

In nano: type, then Control-O to save, then Control-X to quit. In vim: press i to type, Esc, then :wq and return to save and quit. :q! quits without saving. Learn the exit before you write a novel.

Do this now

cd /tmp/c0-3
nano notes.txt

Type three lines. Save. Quit. You should be back at the prompt. Then run cat notes.txt and see your lines.

The same folder in a GUI editor

Open the same /tmp/c0-3 folder in VS Code or another GUI editor. Change one line. Save. Back in the terminal, cat notes.txt again.

If the text did not change, you edited a different copy. Find the real folder. Do not keep two trees.

Do this now

cat /tmp/c0-3/notes.txt

The file matches what you saved in the GUI editor. One tree, not two.

The run loop

You work in a directory that is the project. You do not spray files across Desktop. You keep the terminal pointed at that directory. You run the program from there so relative paths mean what you think.

You read an error from the top. File, line, message. Then you go to that line on purpose.

Copy and paste from the web will waste a day of C1 if you do not look at what you pasted. Curly quotes and mixed tabs are not theoretical. Set the editor to show whitespace and to use spaces.

Do this now

Without a mouse if you can, switch from editor to terminal, run ls, switch back.

The loop is the skill. The clock time does not matter.

Implement

Closed-resource terminal drills. No Bandit walkthrough. No solutions on this site.

  1. Pick one GUI editor, VS Code or equivalent, and one terminal editor, nano or vim. Write the names in the work log so I know which pair you own.
  2. In the terminal editor, create notes.txt in /tmp/c0-3. Write three lines. Save. Quit. cat the file from the shell. If you cannot quit, that is the assignment. Learn the exit. Do not force-kill the window.
  3. In your GUI editor, open that same folder. Change one line. Save. Back in the terminal, cat again. Confirm you are looking at one tree.
  4. Without a mouse if you can, switch from editor to terminal, run ls, switch back.
  5. Do not install a vim config from the internet. Do not install twenty VS Code extensions. If AI autocomplete is on, turn it off for C0.
