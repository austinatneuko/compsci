Teaching

Persistence patterns are how you keep C6 from becoming a ball of handlers. A function that is the order should not know FastAPI. A function that is the row should not know status codes. This is C4's ADT sermon on a database. Domain functions do not import the web framework.

We will introduce an ORM only after you can write the SQL. If we use one, you will still log or print the SQL for a join so you are not surprised. If we do not, you will keep parameterized SQL in one module. Either way, handlers stay thin.

Transactions live in the use-case function, not sprinkled in helpers that you forget to compose. Connections have a lifetime. Leaking connections is how a service dies at 50 users.

P1 will be this service grown up. If the seams are wrong now, we fix them now. The mastery drill is a new prompt: schema, API, tests, one index explained. That is the C6 exit in the program text.

Backend work in this program is HTTP plus a relational database plus a thin framework, in that order. FastAPI is not the syllabus. If you cannot read a raw request, predict a join, or justify an index, a green OpenAPI page is decoration. We talk to Postgres with parameters before any ORM. Transactions are how two writes become one fact. Validation dies at the edge with a 4xx that names the field. The service you build here is the skeleton of P1.
