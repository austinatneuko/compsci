Immutability and HOFs

C4 Software Construction

Locked. Because the prerequisite course is not mastered. You are on C0.1. You may read so the catalog is a real map. Do not start the exercises or the assigned reading until this lesson is current. Ratings do not move from a URL.

Objectives

  • Use immutability as a default for values that do not need to change.
  • Write a higher-order function: a function that takes or returns a function.
  • Map and filter as ideas, not as a personality that bans loops.
  • Keep this in Python. We are not opening a second language.

Teaching

Functional programming as a semester is excluded from this program on purpose. The ideas that pay rent are not. Immutable values are easier to reason about. If the list cannot change, the alias bug from C1.4 dies. Prefer returning a new collection when the cost is fine. Mutate when the cost or the API demands it, and then say so. Immutability is a default for values that do not need to change, not a ban on lists.

A higher-order function takes a function or returns one. sorted(xs, key=...) is one you already used. You will write once(fn) or a simple compose, and a map/filter that you could also have written as a loop. If you cannot expand the comprehension or the map to a loop, write the loop. Cleverness is not the exit. Higher-order functions are how sorted and a test hook work.

Closures capture names. That is useful and sharp. A default-argument-in-a-loop bug will show up. We will poke it until you fear it. Lambdas stay one expression. If you need statements, def.

This module exists so C7 TypeScript and C10 concurrency do not introduce don't share mutable state as a foreign religion. You will have already practiced the taste. We are not opening a second language. We are practicing a taste C7 and C10 will assume.

Rewrite a mutating function to return a new value. Tests still express the spec. Closed-resource: expand a map/filter to a loop on paper. If the paper is I just know, we do another one.

C4 is the course where other people have to live with your code. Specs, ADTs, tests, PR-quality Git, review, a debugging method, API-shaped errors, a little FP taste, and AI evaluation as law. MIT 6.1020 is the gold statement of the ideas; we do the work in Python. Google engineering practices are a baseline, not scripture. Dual-track work starts here: closed first, then catch the model. If you treat this course as a checklist of tools, you will still write a 400-line main. If you treat it as contracts plus history plus review, P1 becomes possible.
