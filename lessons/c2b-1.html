Heaps

C2-remainder Data Structures remainder

Locked. Until Gate A. Systems depth and remaining CS wait until you can apply. You may read so the catalog is a real map. Do not start the exercises or the assigned reading until this lesson is current. Ratings do not move from a URL.

Objectives

  • Implement a binary heap: push, pop-min (or max), peek.
  • State the array layout and the bubble rules.
  • Use it as a priority queue in one small problem.
  • Name when a sorted array beats a heap.

Teaching

A heap is a tree that is almost complete, stored in an array, with the heap property (parent ≤ children for a min-heap). Push appends and bubbles up. Pop-min swaps root with last, shrinks, bubbles down. Both are logarithmic in the number of items. C2-lite deferred this; interviews and Dijkstra (C5-remainder) use it.

You will implement it. Tests: empty pop raises, a sequence of pushes pops in order. Drawing the array as a tree is mandatory once.

A sorted array is better if you build once and only read min, or if n is tiny. A heap is better if you interleave pushes and pops. Say it.

C2-remainder is what lite skipped: heaps, graphs as ADTs, and any implementation that was thin. You will implement a heap and a graph, state costs, and name when each loses. Implement-everything studio is the same exit energy as C2.6 with a larger deck. Interviews that wander into heaps after the gate will not be your first meeting with a bubble-down.

Array layout: children of i sit at 2i+1 and 2i+2. Bubble up on push, down on pop. Empty pop raises. A sorted array wins if you build once and only read min. Interleaved push and pop is the heap's job. Draw the array as a tree once.

Remainder is honesty about what lite skipped. If you cannot implement a heap, you do not have a heap. If you cannot hide a graph representation, you do not have an ADT. Studio conditions are closed and timed. Costs include the counter-case: when the structure you love loses. That sentence remains mandatory.
