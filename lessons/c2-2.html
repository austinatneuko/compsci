Linked lists

C2-lite Data Structures (pre-gate)

Locked. Because the prerequisite course is not mastered. You are on C0.1. You may read so the catalog is a real map. Do not start the exercises or the assigned reading until this lesson is current. Ratings do not move from a URL.

Objectives

  • Implement a singly linked list with head (and tail if you need it).
  • Walk, insert at head, delete a node you can name.
  • Contrast index cost with arrays.
  • Draw boxes and arrows; refuse to debug a list only by printing.

Teaching

A linked list stores each item in a node that points at the next. There is no arithmetic index. To get the k-th item you walk k steps. That is the whole trade: inserts and deletes at a position you already hold can be cheap; random access is not.

You will write Node and LinkedList. Head is mandatory. Tail is a gift for append. Off-by-one bugs live at the empty list, the one-node list, and the last node. Tests that skip those are theater. I will not accept a list that only works when it already has three elements.

Mutation is pointer surgery. Draw the arrows before you write the assignment statements. If you assign in the wrong order you lose the rest of the chain. This is the first structure where “run it and see” is slower than a 20-second sketch.

We are not building deque from scratch to be cute. We are making sure that when C2.3 wraps this as a queue, you know what the wrap is hiding. Python’s list remains the default sequence in application code. Linked lists are here because interviews and systems still use the idea, and because you cannot choose a structure you have never felt.

C2-lite is judgment plus implementation, not a museum of types. A structure is the operations you need and the bill they send when n grows. You already use lists and dicts; now you must be able to build the ones a junior actually needs and say when a list beats a hash. Heaps and graphs-as-ADTs wait until after the gate. That is not because they are optional forever. It is because the hiring bar uses lists, hashes, and trees, and we will not pretend you implemented a heap if we did not sit with one. Every module ends with costs you can say out loud.

The empty list and the last node are not edge cases you add after the happy path. They are the path. A function that walks until next is None will skip a one-node list if you wrote the loop wrong. Tests that only use three nodes are how those bugs ship. Draw every pointer assignment as two pictures: before and after. If you cannot, do not type yet.

Work

Exercises are listed so you can see the shape of the work. They are not assigned. Do not start them. No solutions on this site.

  1. Implement singly linked list: push_front, pop_front, find, insert_after, to_list. Tests include empty and one-node.
  2. On paper, draw insert_after on a three-node list. Bring the drawing.
  3. Write two sentences: when a linked list beats a dynamic array, and when it loses badly.
  4. Closed-resource. No solutions from the web. Timed quiz.
