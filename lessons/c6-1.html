HTTP and the web as a system

C6 Backend Systems

Locked. Because the prerequisite course is not mastered. You are on C0.1. You may read so the catalog is a real map. Do not start the exercises or the assigned reading until this lesson is current. Ratings do not move from a URL.

Objectives

  • Describe HTTP as request and response over a connection, not as the internet.
  • Name method, path, headers, body, and status as the parts you will actually use.
  • Explain idempotence for GET vs POST at a user level.
  • Read a raw request and say what the server was asked.

Teaching

The web is a system. A client sends a request. A server sends a response. HTTP is the text-ish protocol they speak. You will stop treating fetch or a framework as the phenomenon. Method, path, headers, optional body: that is the ask. Status code, headers, body: that is the answer. Everything else in C6 sits on this picture.

Read a request as text before you read a framework object. I will give you raw HTTP/1.1 on the wire or in a log. If you cannot read it, you cannot debug a proxy, a load balancer, or a wrong Content-Type. Frameworks hide this. Hidden is not gone.

Status codes are a language. 2xx did the job. 4xx the client's request is the problem, including 404 and 401 and 403, which are not the same. 5xx the server failed. Returning 200 with an error object is a habit we will break unless you can defend it. I will make you read MDN, not a random blog's codes cheatsheet with jokes.

Idempotence: doing it twice has the same effect as once. GET is supposed to be safe and idempotent. POST is neither by default. PUT can be idempotent if you designed it that way. This is not trivia. Retries, refresh buttons, and payment endpoints all live here. You will say the word about an endpoint you write, later. If you cannot say whether a POST can run twice, you do not have an API yet. You have a handler.

No framework yet. No AI summary of HTTP. I want your sentences. From MDN, when I assign it, write five sentences: GET, POST, 404, 500, Content-Type. If those sentences could appear in any course unchanged, they are too vague. Name what the client asked and what the server claimed.

Backend work in this program is HTTP plus a relational database plus a thin framework, in that order. FastAPI is not the syllabus. If you cannot read a raw request, a green OpenAPI page is decoration.
