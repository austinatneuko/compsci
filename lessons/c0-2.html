Filesystem and permissions

C0 Computing Environment

Locked. Because C0.1 The Shell is not mastered yet. You may read so the catalog is a real map. Do not start the exercises or the assigned reading until this lesson is current. Ratings do not move from a URL.

Objectives

  • Describe a filesystem as a tree of names, not as “folders on a desktop.”
  • Move around with a working directory: where you are is part of every command.
  • Read a permission triple and say who may read, write, or execute a file.
  • Use a pipe as “the output of this becomes the input of that,” not as magic syntax.
  • Treat permission denied and no such file as information, not as insults.

Teaching

A disk is not a pile. The operating system gives you a tree of names. Each name is either a file (bytes with a type the OS mostly does not care about) or a directory (a list of names). The desktop folders you already know are one view of that tree. The shell’s view is the same tree, spoken in paths. A path is an address: a sequence of names from some starting point down to the thing you meant.

Two starting points matter. An absolute path starts at the root of the tree — the directory that contains everything else. A relative path starts at your working directory, which is simply “where the shell thinks you are right now.” Beginners fight the machine because they type a name that exists, but not here. The file is real. Your address is wrong. pwd, ls, and cd are not trivia. They are how you ask “where am I,” “what is here,” and “move.” Until those three are boring, every later command will feel haunted.

Names can contain almost anything. Spaces make lines harder to read; we will quote them. Hidden names in Unix start with a dot. That is a convention, not encryption. ls without flags will politely omit them. The files are still there.

Permissions are the first security model you will actually use. Every file carries a short statement: what the owner may do, what the group may do, what everyone else may do, for read, write, and execute. Execute on a directory means “you may enter it,” not “it is a program.” Execute on a file means “the kernel may run this as a program” — which is why a script you wrote can sit there looking perfect and still refuse to run. When the shell says permission denied, it is not being difficult. It is enforcing a rule someone set, sometimes you.

You do not need to memorize every octal. You do need to read ls -l out loud: type, owner, group, size, date, name. You do need to know that downloading a script from the internet and running it is a permissions decision and a trust decision, and those are not the same.

Pipes are the reason the shell is more than a program launcher. A program writes bytes to standard output. Another program reads bytes from standard input. A pipe connects those two streams so you never make a temporary file you will forget to delete. This only works well because Unix tools were written to do one job and speak text. grep does not know about your homework. It knows about lines. You will learn a small set of filters — list, find, search, sort, count — and compose them. Composition is the skill. Collecting flags is not.

Redirects are the sibling of pipes: send output to a file, or take input from one. > replaces; >> appends; mixing them up is how people erase work. We will practice on disposable files first.

The work of this lesson is navigation and reading, not clever one-liners. I would rather you be slow and oriented than fast and lost. Bandit, when I assign levels, is a game that forces this orientation. I will not give you walkthroughs. If you paste a level into a search box you will get an answer and lose the lesson.

Work

Exercises are listed so you can see the shape of the work. They are not assigned. Do not start them. No solutions on this site.

  1. Closed-resource first. On a real machine, from a terminal: print your working directory. List what is there, including hidden names. Change into a directory and back out. Draw the path as a tree on paper.
  2. Create a disposable directory. Write a small text file into it using the shell (not a GUI save dialog). Copy it. Rename it. Delete the copy. List after each step so you see the tree change.
  3. Run ls -l on that file. In chat, read the permission triple out loud in English: who can read, write, execute.
  4. Pipe the output of ls into a command that counts lines. Then redirect the same listing into a file. Open the file and confirm it is what you saw.
  5. Do not start Bandit until I assign specific levels in CompSci chat. No walkthroughs, ever.

Mastery

From a cold prompt, you can say where you are, list a directory, follow a path, read permissions in English, and connect two programs with a pipe. You can explain a permission denied without guessing. Demonstration on a terminal, not on this page.
