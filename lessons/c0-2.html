Definitions

filesystem
A tree of names the operating system keeps on disk.
path
An address that walks from a starting folder down to a file or folder.
hidden name
A name that starts with a dot. ls skips it unless you ask.
permission
A rule that says who may read, write, or run a file.
standard output
The text stream a program prints by default.
pipe
A connection that sends one program's output into the next program's input.
redirect
A way to send output to a file, or take input from a file.

The desktop folders you know are one view of this tree. The shell uses paths.

The tree of names

A disk is not a pile. The operating system gives you a tree of names. Each name is a file or a folder. A folder is a list of names. A path is an address down that tree.

You already saw absolute and relative paths. This chapter is the tree itself, the listing, the hidden names, the permission line, and how text moves from one program to another.

Do this now

pwd
ls
ls -F

pwd prints where you are. ls prints names here. ls -F marks folders with a /.

List and move

ls names what is in a folder. ls /tmp names what is in /tmp without moving you. cd /tmp then ls names the same thing after you have moved.

ls -a also prints hidden names. ls -l prints a long line: type, permissions, owner, group, size, date, name. Learn to read that line out loud.

Do this now

cd ~
ls -a
ls -l

You should see . and .. in the -a list. You should see permission strings such as drwxr-xr-x in the -l list.

Hidden names

A name that starts with a dot is hidden by convention. It is not encrypted. ls without -a omits it. The file is still there.

Your shell reads ~/.zshrc when it starts. That file configures zsh. If you "delete a project" and leave a .git folder, you left the real history. We will meet .git in C0.4.

Do this now

ls -a ~
ls ~

The first list is longer. Names that start with a dot appear only in the first list.

Permissions

Every file carries a short statement of what the owner may do, what the group may do, and what everyone else may do, for read, write, and execute.

Execute on a folder means you may enter it. Execute on a file means the kernel may run it as a program. That is why a script you wrote can sit there looking perfect and still refuse to run.

When the shell says permission denied, it is enforcing a rule. Read the rule before you change it.

Do this now

ls -l ~ | head -n 5

Each line starts with a type character, then nine permission characters. Say one line in English.

Pipes

A program writes bytes to standard output. Another program reads bytes from standard input. A pipe connects those two streams. You type | between the programs.

This works well because Unix tools were written to do one job and speak text. ls does not know about your homework. wc -l counts lines. You compose them.

Do this now

ls ~ | wc -l

A number. That number is how many names ls printed, counted as lines.

Redirects

> file sends standard output to file and replaces whatever was there. >> file appends. Mixing them up is how people erase work. Practice on disposable files.

< file feeds a file to a program as input. You will use > more often this week.

Do this now

ls ~ > /tmp/c0-2-listing.txt
cat /tmp/c0-2-listing.txt
rm /tmp/c0-2-listing.txt

cat should print the same names ls printed. Then the file is gone.

Implement

Closed-resource terminal drills. No Bandit walkthrough. No solutions on this site.

  1. From a cold prompt, print your working directory. List what is there, including hidden names. Change into a folder and back out. Draw the path as a tree on paper or in the work log.
  2. Create a disposable folder under /tmp. Write a small text file into it using the shell, not a Save dialog. Copy it. Rename it. Delete the copy. List after each step.
  3. Run ls -l on that file. In the work log, read the permission triple in English. Who can read, write, execute.
  4. Pipe the output of ls into wc -l. Then redirect the same listing into a file. Open the file and confirm it is what you saw.
