Strings and files

C1 Programming Fundamentals in Python

Locked. Because C0 module 3, editor and terminal workflow, is not mastered yet. C1 can start in parallel only after that. You may read so the catalog is a real map. Do not start the exercises or the assigned reading until this lesson is current. Ratings do not move from a URL.

Objectives

  • Treat a string as an immutable sequence of characters. Build new strings rather than changing one.
  • Open a text file, read it, write it, and close it, preferably with with.
  • Know the difference between a path, a file object, and the string contents.
  • Handle newlines and encoding as real choices, not as surprises.
  • Write a small program whose input is a file and whose output is a file or a returned structure.

Teaching

A string is an immutable sequence of Unicode characters. You index and slice it like a list. You cannot assign to an index. Methods like strip, split, join, replace, lower return new strings. split without arguments splits on whitespace and throws away empty pieces. split(",") does not. join is a method on the separator, which feels backwards the first week and then does not. Concatenating strings in a loop with + works for homework sizes and is the wrong habit for large work. We will mention join or a list of pieces and move on.

Text processing is mostly normalize, split, decide, reassemble. Normalize means decide what to do with case, punctuation, and extra space before you count or compare. If you skip that, your word counts become a census of your indecision.

Files are bytes on disk with a name in the tree you learned in C0.2. open(path) gives you a file object, a cursor into those bytes. .read() pulls the rest as one string. .readline() pulls one line. Iterating the file object walks lines, including the newline character at the end of each. That newline will show up in your counts if you do not strip. with open(path) as f: is the form I want. It closes the file when you leave the block, including when you leave because of an exception.

A path is a string, or a Path. It is not the file. Two programs can hold different file objects on the same path. Working directory still matters. A relative path is relative to where you launched Python, not to where the .py file lives, unless you made it so. That C0 skill just became a C1 bug. I will not accept I ran it in the editor as an explanation when the file is sitting one directory over.

Encoding. Text is Unicode. Disk is bytes. UTF-8 is the default we will use. If you open a file and see mojibake, you have an encoding mismatch, not a Python string problem. For this course, write UTF-8, open UTF-8, and do not paste Word's smart quotes into a .py file.

Write as well as read. open(path, "w") truncates. That word means erase and start over. "a" appends. Opening with "w" on the wrong path is how people lose work. We practice on disposable files. We keep real work in Git so a bad open is recoverable.

A small program in this lesson has a job you can say. Read a text file, produce a structure, list of lines, word counts, a filtered file. Return or write. Tests in C1.7 will thank you if the function takes a path or a file-like object and returns data, instead of printing a novel.

Work

Exercises are listed so you can see the shape of the work. They are not assigned. Do not start them. No solutions on this site.

  1. Write count_lines(path) that returns the number of lines in a text file. Use with. Write a tiny fixture file in the repo and run against it.
  2. Write a function that reads a file and returns a dict of word to count. Define word in the docstring. You choose a simple rule and stick to it. Closed-resource.
  3. On purpose, open a file with "w" that you meant to read. See what happened. Restore from Git. Write one sentence in chat about why "w" is a loaded gun.
  4. Take a multiline string in a test file and split it as if it had come from disk, splitlines. Compare with .split("\n"). Note the difference.
  5. Homework program, a filter. Read a file, write another file containing only the lines that match a rule you specify, length, prefix, whatever you pick. Commit both the program and a sample input.
