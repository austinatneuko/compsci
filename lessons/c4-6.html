Debugging method

C4 Software Construction

Locked. Because the prerequisite course is not mastered. You are on C0.1. You may read so the catalog is a real map. Do not start the exercises or the assigned reading until this lesson is current. Ratings do not move from a URL.

Objectives

  • Debug with a hypothesis: what would be true if I were right, how do I check.
  • Use a stack trace, a repro, and a bisection of the search space.
  • Stop changing three things at once.
  • Write down the path so the next bug is cheaper.

Teaching

Debugging is not hoping. You reproduce, you form a hypothesis, you run the smallest check that could kill the hypothesis, you update. Print is legal. A debugger is legal. Changing a line at random while a model rewrites the file is not a method.

The scientific loop is the same as C0.5, now on your code. It doesn't work is not a report. Given input X, I expected Y, I got Z, I think function f dropped the last item because the slice is off is a report. If you cannot reproduce, you do not have a bug you can fix. You have a story.

I will give you broken programs. Some fail tests. Some fail only on an edge. Some fail because the environment is wrong, PATH or cwd. You will write the hypothesis first in chat, then the check. Lucky fixes you cannot explain get reverted and redone. Changing three things at once is how you lose the lesson and keep the bug.

The debug note is part of the work: repro, hypotheses, checks, conclusion. AI is off on the first debugging assignments. A model will shotgun patches. Shotgun patches teach you nothing and sometimes introduce a second bug you then owe the model. The gate debugging exam is this method under a clock.

Do not reinstall Python. Do not ask a model. Three broken programs from me. Hypothesis first, then fix. Keep a debug note for one of them. If the note is I fixed it, we redo the note, not only the program.

C4 is the course where other people have to live with your code. Specs, ADTs, tests, PR-quality Git, review, a debugging method, API-shaped errors, a little FP taste, and AI evaluation as law. MIT 6.1020 is the gold statement of the ideas; we do the work in Python. Google engineering practices are a baseline, not scripture. Dual-track work starts here: closed first, then catch the model. If you treat this course as a checklist of tools, you will still write a 400-line main. If you treat it as contracts plus history plus review, P1 becomes possible.
