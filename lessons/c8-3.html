Integration tests

C8 Auth, Quality, Delivery

Locked. Because the prerequisite course is not mastered. You are on C0.1. You may read so the catalog is a real map. Do not start the exercises or the assigned reading until this lesson is current. Ratings do not move from a URL.

Objectives

  • Write an integration test that hits HTTP and database, not just a pure function.
  • Keep them few, slow-but-honest, and deterministic.
  • Test a permission fail, not only the happy path.
  • A green unit suite with no integration test is not enough for C8.

Teaching

Unit tests still matter, C4. Integration tests check that the seams meet: handler, auth, SQL, status code. You will spin a test database or a transaction rollback scheme I approve. Hitting prod from a test is a fail. An integration test hits HTTP and the database.

They are slower. So you write fewer, on the paths that would embarrass you: signup, login, create-a-thing, cannot-read-another-user's-thing. If those are green and your units are green, I will believe more than if you have 200 units and zero HTTP tests. Two hundred unit tests and zero HTTP tests is how authz holes ship.

Determinism: no sleep for three seconds, no real network to a third party, fake it, no dependence on wall-clock without freezing it. Flaky tests get deleted or fixed. They do not get run again. Sleeping in a test is a fail. Hitting production from a test is a fail.

Add integration tests for authz fail and one create path. CI will run them in C8.4. Closed-resource. No AI-generated 40-file test harness. A permission fail is tested through HTTP, not only in a helper.
